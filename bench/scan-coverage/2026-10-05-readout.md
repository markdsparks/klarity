# Scan-coverage read-out — 2026-10-05 (baseline)

300 real US grocery barcodes (10 × 30 aisles, Kroger catalog sample) through the app's own `ScanResolver` +
`classifyOutcome`. Aggregates only; raw runs are gitignored.

## Baseline

| outcome | share |
|---|---:|
| confident (full two-axis verdict) | 33% |
| clean (no additives + nutrition) | 20% |
| unrated-additive | 42% |
| thin-nutrition / regulatory-only | 3% |
| **error screen** ("Could not load product.") | 3% |

OFF had 291/300; USDA matched 34%; ingredient text 98%; usable nutrition 97%. The audit detector found
**0 false "clean"** verdicts — when we say clean, it held up.

Weakest aisles (≤1/10 full verdict): crackers, frozen pizza, sports drinks, cereal, granola bars, snack cakes,
coffee creamer, bread, protein bars.

## Findings, ranked

1. **OFF "not found" is an HTTP 404 → the scan errors instead of falling back.** OFF v2 answers a missing
   product with `404 {"status":0}`; `OFFClient.requestJSON` throws on 4xx, so `ScanResolver.resolve` throws
   before spec 021 M3's USDA/Kroger synthesis runs. Every product OFF lacks shows "Could not load product."
   and isn't logged in diagnostics. All 9 errors here were this; Kroger had all 9. (Likely worse on store
   brands, which this popularity-ordered sample under-represents.) Related: an OFF 429/5xx also fails the
   whole scan even when USDA/Kroger resolved.
2. **E-number sub-variants lose their evidence.** OFF tags `en:e322i`, `en:e500ii`, `en:e341i`…; the index
   only knows the parent (E322 lecithin, E500 sodium bicarbonate, E339 sodium phosphates are *hand-authored*).
   Result: an unnamed "E322I" row and an `unrated` outcome. Parent fallback alone: confident 33% → 54%,
   unrated 42% → 20% (simulated on this run).
3. **Ten missing evidence entries cover most of what's left:** E150c ammonia caramel (23 products),
   E341 calcium phosphates (35 incl. E341i), E316 sodium erythorbate (18), E340 potassium phosphates (17),
   E422 glycerol (15), E331 sodium citrates (13), E160c paprika extract (13), E450 diphosphates (13),
   E472e DATEM (9), E428 gelatin (5). With #2: confident ≈ 68%, unrated ≈ 6%.
   Several of these (E341, E331, E160c, E450, E428) aren't even in the EFSA regulatory tier — an ingestion gap.
4. **Text-only detection gaps** (only matters when OFF tags are missing — USDA/Kroger text paths):
   yeast extract (27), calcium sulfate (13), sodium acid pyrophosphate (11), propylene glycol (7) appear in
   ingredient text with no alias in the engine.

## Projected after #1–#3

Full verdict ≈ 68% · full-or-clean ≈ 88% · unrated ≈ 6% · error screen 0%.

Re-run with `npm run bench:scan` after each fix to confirm against the same 300.

## Re-run 2026-10-08 — after fixing #1 and #2

| outcome | 10-05 | 10-08 |
|---|---:|---:|
| confident | 33% | **54%** |
| clean | 20% | 20% |
| unrated-additive | 42% | **21%** |
| thin-nutrition / regulatory-only | 3% | 6% |
| error screen | 3% | **0%** |

All 9 former errors now resolve via Kroger identity (mostly `thin-nutrition` — Kroger carries ingredients, not
nutrition, so the additive axis is real and the nutrition axis honestly says it has nothing).

Scoped deliberately: an OFF *outage* (429/5xx/offline) still shows the error rather than a Kroger-only result.
A first attempt masked outages too, and the bench caught the cost — rate-limited products rendered as "No
nutrition data on file", which is false when the data exists but was unreachable. Doing that honestly needs
its own "couldn't reach nutrition data" state (a copy/spec decision), not a silent fallback.

Next lever (#3): the remaining unrated list is now led by E150c, E341, E316, E340, E422, E160c, E331, E472e.

## Found while verifying on screen: "No additives" with no ingredient list

The rescued not-in-OFF products (and 10/300 overall) have no ingredient list from any source, and the engine
scored that as "No additives" — a false clean, against CLAUDE.md's "never score missing data as zero". Same
bug, larger, in restaurants: every Panda Express (120) and Panera (16) item is nutrition-only and showed a
green "No additives". The additive axis now has its own "No data" state (the spec 025 twin): not tappable,
an honest sentence ("…so this covers nutrition only"), and a `no-ingredients` diagnostics outcome.
