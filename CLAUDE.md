## What Klarity is

An evidence-tiered food scanner — a calibrated alternative to Yuka. Same one-second scan UX, but:

- **Calibrated to evidence + dose**, not ingredient presence (no false alarms)
- **Two axes, never combined**: nutrition (macros/micros) AND additives (evidence tier × exposure)
- **Three verdict states**: `everyday` · `sometimes` · `contested` (we never fake a side when regulators disagree)
- **Personalized**: profiles shift how contested cases resolve and surface subgroup notes
- **Evidence trail visible**: every verdict shows the tier (A/B/C/D) and the "why"

Primary user: Mark's family — replacing Yuka for real grocery shopping. Make it that good first.

## Tech stack (ADR-007 — native since cutover, 2026-10-01)

| Layer | Choice | Why |
|---|---|---|
| App | **Swift 6 + SwiftUI**, iOS 26+, project generated by **XcodeGen** (`native/project.yml`) | Native sheets, scanner, materials; no JS runtime (ADR-007 supersedes ADR-001/004/005) |
| Engine | **`swift/KlarityCore`** Swift package — all evidence, nutrition, verdict, search, restaurant and Q&A logic | Pure, tested, UI-free; shareable with Fettle later |
| Scanning | **VisionKit `DataScannerViewController`** | System barcode scanner; handles didAdd + didUpdate (payload often arrives late) |
| On-device Q&A | **Foundation Models** guided generation → deterministic dispatch (spec 014 native addendum) | The model only classifies; it never writes claims |
| Product data | Open Food Facts + USDA FoodData Central + Kroger (via the token proxy in `server/`, ADR-006) | Unchanged sources |
| Evidence data | **Bundled JSON in `swift/KlarityCore/Sources/KlarityCore/Resources/`** — canonical, hand-edited (EFSA file generated) | Was TS until cutover |
| Persistence | JSON files in Application Support + UserDefaults (profile, servings) | Same shapes as the RN app's AsyncStorage; `LegacyImport` adopted it at cutover |

## Evidence tier model (from spike — do not change without discussion)

```
Tier A — Regulatory consensus / human trial
Tier B — Human observational / limited human data
Tier C — Animal data
Tier D — In-vitro only, OR misattributed / wrong-substance
```

Verdict states: `everyday` · `sometimes` · `contested`

The key editorial rules:
1. **Never mash nutrition and additives into one score.** Two axes, always separate.
2. **Dose and frequency matter.** "This ingredient exists" is not a verdict.
3. **Contested means contested.** Show both sides; don't pick one to make the UI simpler.
4. **Tier D evidence that misattributes substance is dismissed, not elevated.** (The carrageenan rule.)
5. **IARC Group 2B = hazard, not dietary risk.** Always pair with intake context.

## Design language

The Klarity design system (brand book, tokens, components): https://claude.ai/artifact/D9bDf7yWgZeN5hztzF1XKq
— see `design/README.md`. Native code: `native/Klarity/Shared/Theme.swift` + `Brand/KlarityMark.swift`.

colors fail 4.5:1 as small text on light grounds); state is shown with `LadderMark`, never colored
card rails; brand mint appears only in the mark and on the ink hero.

## Dev workflow

```bash
npm run native:gen     # .env → Config/Secrets.xcconfig, then regenerate Klarity.xcodeproj (after adding files too)
npm run test:swift     # engine tests (golden parity fixtures + unit tests)
```

Testing loop, fastest first:
1. **`npm run test:swift`** — every engine change. Golden fixtures in `Tests/.../Golden` were generated
   from the TS engine before it was deleted; they are now frozen regression fixtures. A deliberate
   behavior change updates the affected fixture in the same commit, with the reason in the message.
2. **iOS Simulator** — build with `xcodebuild … -destination 'platform=iOS Simulator,name=iPhone 17 Pro'`
   and drive it with the Simulator tools. Search, results, restaurants, sheets, history and Ask about this
   (Apple Intelligence works in the Simulator) are all testable. No camera.
3. **Mark's iPhone** — `xcodebuild … -destination 'id=<udid>' -allowProvisioningUpdates`, then
   `xcrun devicectl device install app` + `process launch --console` to stream logs. Needed for the scanner.
4. **TestFlight** — release channel for the family, not a testing channel.

## What NOT to do

- **Do not combine nutrition and additive scores into one number.** Ever.
- **Do not flag an additive as dangerous based on Tier D / misattributed evidence.** That's the whole point.
- **Do not score missing data as zero.** No data is its own honest state (spec 025, the potassium copy fix).
- **Do not let the on-device model write user-facing text or claims.** It classifies; the engine answers.
- **Do not add third-party dependencies without discussion.** System frameworks first.
- **Do not commit directly to main for features.** Branch + PR (squash merge).
- **Do not invent URLs or scrape sites.** Only use documented APIs from evidence-sources.md.

## Build & deploy

```bash
npm run build:native    # archive + export → native/build/export/Klarity.ipa (signed, App Store Connect)
npm run submit:native   # eas submit --path → TestFlight (EAS holds the App Store Connect API key)
```

- **Build number:** bump `CURRENT_PROJECT_VERSION` in `native/project.yml` above the last uploaded build
  (29 at cutover). EAS's remote counter is stale for local builds — trust the higher of it and the last
  uploaded value.
- **Signing prerequisite:** Xcode → Settings → Accounts must be signed into the Apple ID for team
  `22PRZ6YK2P` — only Mark can do this; never script Apple ID credentials. Without it the export fails
  with "No Accounts".
- **`submit:native` can hang locally** after "Scheduled iOS submission" while the EAS server keeps going;
  the submission still completes. Check TestFlight in App Store Connect rather than waiting on the CLI.
